## HIGH

### H-1. Event pages render with unstyled nav + footer

Affects all 21 `/events/:slug` pages — the primary SEO/GEO landing surface (in sitemap, indexed, users arrive from search).

Cause: `lib/seo/event-page.js` `navFragment()` emits classes `.navbar`, `.nav-container`, `.nav-logo`, `.nav-menu` and `footerFragment()` emits `.footer-inner`, `.breadcrumbs`. The page's only external stylesheet is `/assets/css/brand.css`, which does **not** define any of those classes (it has `.nav-links`, `.logo`, `.footer-container`, `.footer-bottom`). The inline `<style>` block only styles `main.event-page`.

Result (confirmed live): top nav renders as default blue underlined links, no bar background/layout; `<h1>` overlaps the unstyled nav. Page body content is correctly styled and functional.

Note: `.hamburger` and `.mobile-menu` *are* in brand.css, so the mobile toggle works on event pages — it's the desktop nav bar + footer chrome that is unstyled.

Recommended fix (self-contained, no brand.css dependency): add nav/footer rules to the existing inline `<style>` in `event-page.js`, e.g.

```css
nav.navbar{position:sticky;top:0;z-index:100;display:flex;align-items:center;justify-content:space-between;
  padding:12px 20px;background:#fff;border-bottom:1px solid #e6e1d8}
nav.navbar .nav-container{display:flex;align-items:center;justify-content:space-between;width:100%;max-width:1200px;margin:0 auto}
nav.navbar .nav-menu{display:flex;gap:24px;list-style:none;margin:0;padding:0}
nav.navbar .nav-menu a{color:var(--charcoal,#2c2c2c);text-decoration:none;font-weight:600;font-size:14px}
nav.navbar .nav-menu a:hover{color:var(--brand-red,#c8102e)}
.breadcrumbs{font-size:.85rem;margin:16px 0;color:var(--slate,#5a5a6e)}
.breadcrumbs a{color:var(--brand-red,#c8102e);text-decoration:none}
footer .footer-inner{max-width:1200px;margin:0 auto;padding:40px 20px;text-align:center}
footer{background:#0a0a0a;color:#fff;margin-top:64px}
/* + .hamburger display:none above 768px, flex below; .mobile-menu styles */
```

Alternative: rewrite `navFragment()`/`footerFragment()` to reuse the markup + inline CSS pattern from `pages/*.html` so all pages share one nav implementation.

### H-2. first-5k.html mobile menu is non-functional

On phones (≤768px), `.nav-links` is `display:none` and `.mobile-menu-btn` shows — but the button has no click handler and there is no menu drawer. Users cannot open the navigation menu.

Confirmed (live JS probe on first-5k):
- `.hamburger`: absent · `#mobileMenu`: absent · `.mobile-menu-btn` onclick: none
- Page loads `nav.js`, but its `toggleMobileMenu()` queries `.hamburger`/`#mobileMenu` (neither exists) → silently no-ops.

Every other page uses the shared pattern (`.hamburger` + `#mobileMenu` + `onclick="toggleMobileMenu()"`) and works.

Recommended fix: replace first-5k's `<nav>` with the standard nav markup used by the other `pages/*.html` (hamburger button + `#mobileMenu`/`.mobile-menu` drawer + the matching `@media (max-width:768px)` rules), so `nav.js` wires up automatically. first-5k is mobile-first (`min-width` breakpoints) while the others are desktop-first — port the nav block carefully or wire `.mobile-menu-btn` to a drawer with its own handler.

## MEDIUM

### M-1. All races labeled `race_type: "running"` — including triathlons

`/api/races`: 15/15 races have `race_type:"running"`. Five are triathlons:
PDX Triathlon Festival · Pacific Crest Endurance Sports Festival · Hagg Lake Triathlon & Trail Festival · Columbia River Triathlon & Endurance Sports Festival · Girlfriends Triathlon & Fitness Festival.

Impact:
- Event page shows `Race Type: Running` for triathlons (`event-page.js` `detailsBlock`).
- schema.org SportsEvent emits `sport: "Running"` for triathlons (`buildSportsEventSchema`, line ~114) — wrong structured data for SEO.
- Homepage filter is **not** affected — it derives tags from the distances text heuristic (`index.html` ~line 2362), not `race_type`.

Fix: set `race_type='triathlon'` for the 5 triathlons in Supabase. Optional defense-in-depth: in `event-page.js`, infer triathlon from distances text when `race_type` is unset/`running` but distances contain "tri".

### M-2. Mangled arrow glyph renders as literal `?`

Two CTAs have a stray `?` where a `→` arrow was intended (other buttons correctly use `→`, e.g. community.html "Bike →", partners.html "Started →"):
- `index.html:2207` — homepage sticky bar: `Register ?`  → `Register →`
- `pages/volunteers.html:906` — `Join the Crew ?`  → `Join the Crew →`

Fix: replace ` ?` with ` →` (or `&rarr;`) in both. (ASCII `?`, not an encoding artifact.)

## LOW / Polish

### L-1. Hardcoded "21" vs 15 live races
`index.html` hardcodes `View All 21 Races` (line 1852) and `21 Premier PNW Events` (1862, 1868). The archive cron has removed past races; `/api/races` now returns 15 upcoming. "21" is the full annual portfolio but the calendar the CTA points to shows 15. Consider deriving the count from the API, or reword ("View Full Calendar" / "20+ events").

### L-2. Empty quarter renders bare header
After archiving, the Jan–Mar section shows its header + subtitle ("Start the year strong…") with no event cards and no empty-state message. Add an empty-state (or hide a quarter section when it has 0 races).

### L-3. Duplicate `toggleMobileMenu()`
Defined both inline in `index.html` (~line 2212) and in `nav.js`. The inline copy lacks the null-guard the nav.js version has. Remove the inline duplicate and rely on nav.js (already loaded).

### N-1. Domain cutover (not a defect)
Canonical URLs, sitemap, and event-page links use base `https://whyracingevents.com` — correct for production. That apex domain currently serves the **old WordPress site**; the rebuild is on `why-racing-site.vercel.app`. Resolves on cutover. Re-verify canonical/sitemap/sticky-bar links resolve to the rebuild once the apex domain is promoted.
